# Sfery Recovered — кандидат 1.45.0

Совместимое обновление обычной Sfery описано в [RELEASE.md](RELEASE.md). `build-update.ps1` собирает установщик; GitHub Actions проверяет обновление на синтетической базе и сохраняет артефакты без публикации релиза. Обычный `build.ps1` по-прежнему собирает отдельную Sfery Recovered.

Редактируемый проект восстановления собственного приложения из `D:\Sfery\local-planner.exe`, SHA-256 `7cd7820f7cae063982c30d3cbd9901152b8eee12173470ad830a322e43830dbd`.

`frontend-dist/` содержит точные HTML/CSS/JavaScript, извлечённые из EXE и распакованные Brotli. Это production bundle React, а не первоначальные TypeScript/TSX-файлы. Форматированная копия JavaScript находится рядом с проектом в `../readable/`.

Для Сферика добавлен вариант `frontend-dist/assets/index-BGD1PF6B-sferik-idle.js`: в ожидании он «дышит» и моргает в повторяемом восьмисекундном ритме, перенесённом из опубликованного [AI Orb Mascot](https://rive.app/community/files/28088-53050-ai-orb-mascot/). Геометрия Сферика и кривые деформации отличаются от исходного Orb; покадровое визуальное совпадение не заявляется. Исходный извлечённый bundle сохранён рядом без изменений; способ преобразования — `work/sfery/enhance-sferik.cjs` от корня рабочего каталога. Настройка уменьшения анимации действует и на новый цикл.

При запуске отдельная заставка использует SVG Сферика: сначала корпус без глаз, затем светящиеся частицы равномерно появляются по всему экрану и с ускорением втягиваются внутрь, глаза открываются, после чего Сферик перемещается к своему месту в интерфейсе. Ритм вдохновлён сценой получения Vengeful Spirit в Hollow Knight; графические материалы игры не используются. Исходники заставки — `work/sfery/sferik-startup.js` и `work/sfery/sferik-startup.css`. Кнопка «Пропустить» и настройка уменьшения анимации позволяют быстро открыть приложение.

`src-tauri/src/` — заново написанная реализация Rust по извлечённым вызовам, моделям, SQL и историческим материалам. Это реконструкция, а не оригинальные Rust-исходники. Доказательства, смещения и хеши находятся рядом в `../contracts/`, `../frontend/` и `../integrations/`.

Взгляд Сферика реагирует раньше корпуса: корпус следует по двум осям с задержкой 85 мс. Выразительные эмоции затихают за 880 мс без повторного подскока, глаза расслабляются чуть позднее корпуса, дыхание плавно возвращается. Короткие реакции на наведение сохраняют прежнюю скорость.

## Сборка и запуск

Требуются Rust MSVC, Microsoft C++ Build Tools с Windows SDK и WebView2 Runtime. Frontend уже собран; npm не требуется.

```powershell
.\build.ps1
.\dist\Sfery-Recovered.exe
```

Выпуск с оптимизацией: `.\build.ps1 -Release`. Проверки: `cargo test --locked --manifest-path src-tauri/Cargo.toml`.

## Данные и совместимость

Новая сборка использует отдельный идентификатор `local.sfery.planner.recovered` и отдельную папку `%LOCALAPPDATA%\local.sfery.planner.recovered`. Старую базу, вложения и авторизацию она автоматически не импортирует. Для тестов можно задать `SFERY_RECOVERED_DATA_DIR` с путём к отдельной папке.

Восстановлены локальные операции задач, сфер, проектов, подзадач, канбана, корзины, темы, вложений и резервных копий. Схема SQLite и синтетический снимок, созданный оригинальным приложением, используются в проверках совместимости.

Cloud API основан на сохранившихся исходниках серверной части; конфликтное объединение написано заново и сверено с оригинальным EXE на локальном тестовом сервере. Telegram использует grammers 0.10 и новые, защищённые Windows DPAPI файлы сессии. Потребуется повторный вход. Настройки клиента Telegram при сборке считываются из проверенной по SHA-256 копии собственного оригинального EXE; в исходный Rust-файл они не записаны. Если оригинальный файл отсутствует, можно задать `SFERY_TELEGRAM_API_ID` и `SFERY_TELEGRAM_API_HASH`.

Точное совпадение исходного алгоритма отбора Telegram-поручений не доказано. Реальные вход в Telegram и обмен с облаком не проверяются автоматически; тесты не подключаются к личному аккаунту. Первоначальные комментарии, имена Rust-функций, TypeScript-типы и приватный ключ подписи обновлений не восстановлены. Автоматическое обновление старым EXE в этой сборке не настроено.

Сравнение на отдельных тестовых данных: 31 сценарий задач и настроек, 132 вызова вложений, 37 сценариев облака и состояние соглашения совпали с оригиналом; видимый текст интерфейса при одинаковом размере окна тоже совпал. Это не подтверждает поведение всех экранов и реальных аккаунтов. Протоколы проверок лежат в `work/sfery/comparison/` от корня рабочего каталога; сводка — в `../verification.json`.
