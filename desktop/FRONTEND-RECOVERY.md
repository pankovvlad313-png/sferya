# Восстановленный фронтенд Sfery

frontend-dist содержит точные HTML, CSS и JS bytes, декодированные из EXE. Это production bundle, а не восстановленные TypeScript/JSX исходники. Исходные имена минифицированных переменных сохранены. Хеши и диапазоны исходного EXE находятся в ../frontend/recovery-manifest.json.

src-tauri/tauri.conf.json — новая конфигурация для пересборки, а не точная копия утерянного файла. CSP повторяет извлечённый литерал; размеры окна, заголовок и bundle.active=false выбраны для восстановленной сборки. Значения исходной конфигурации и диапазоны записаны в ../tauri-config-evidence.json. Извлечённая иконка сохранена в src-tauri/icons/icon.ico.

Идентификатор намеренно изменён с local.sfery.planner на local.sfery.planner.recovered. Tauri app_data_dir/app_local_data_dir при стандартном разрешении путей используют новый идентификатор. Backend восстановленной сборки должен дополнительно хранить базу и вложения только в этом новом app data каталоге (желательно внутри отдельного recovery подкаталога) и не делать автоматический поиск, миграцию или импорт исходной базы/Telegram сессии. Эта конфигурация сама не ограничивает произвольные пути нативного Rust backend. Asset protocol ограничен каталогами данных новой сборки.

Оригинальная updater endpoint и public key сохранены как доказательства, но не включены в новую конфигурацию: восстановленная сборка не должна автоматически заменяться оригинальным релизом. Backend и обработчики команд собираются отдельно.
